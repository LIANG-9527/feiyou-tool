# 代码关系图使用约定（graphify）

> 用途：改代码前先查关系图确认影响面，不再靠临时 grep 枚举调用方（2026-09-19 定版）。

## 一、手动用法（自己在终端跑，项目根目录下执行）

### 建图 / 更新
| 命令 | 说明 |
|---|---|
| `graphify update .` | **日常首选**：增量更新已改动的代码，纯本地秒级 |
| `graphify extract . --code-only --out graphify-out` | 全量重建（首次或大重构后） |
| `mv graphify-out/graphify-out/graph.json graphify-out/` | extract 后如产生子目录，用这条归位 |

### 查询（改代码前必查）
| 命令 | 说明 |
|---|---|
| `graphify explain "函数名"` | 该函数的全部调用方/被调用方/所在位置 |
| `graphify affected "函数名"` | **改前必查**：这个函数被改会波及哪些节点（反向遍历） |
| `graphify path "A" "B"` | 两个概念之间是怎么连起来的（最短路径） |
| `graphify query "自然语言问题"` | 按问题搜子图（结果偏噪，建议优先用上面三个） |
| `graphify god-nodes` | 全库连接数最高的枢纽节点（改动高危区名单） |

### 看图
- 浏览器打开：**http://127.0.0.1:8777/graph/graph.html**（服务在线时；离线可直接双击 graphify-out/graph.html）
- 文字版摘要：graphify-out/GRAPH_REPORT.md

## 二、自动用法

| 方式 | 说明 |
|---|---|
| AI 助手工作流（默认已生效） | 我改任何函数/接口前，自动先跑 `explain`/`affected` 确认影响面再动手；你无需做任何事 |
| `graphify watch .` | 挂后台常驻，文件一保存自动重建图（代价：常驻进程占少量资源）。启动后 Ctrl+C 停止 |
| `graphify update .` | 不想挂常驻进程时的折中：改完一批后手动跑一次，秒级 |

## 三、边界
- 图只覆盖 Python 结构；main.py 等文件里内嵌的 HTML/JS（页面交互）不进图，前端改动仍需人工过。
- 建议节奏：日常改完一批代码跑一次 `graphify update .`；大重构后全量重建。
