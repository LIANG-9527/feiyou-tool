# 经验复盘：ZSTEK 体检暴露的系统性问题（2026-09-09）

> 背景：jianyongl6.sg-host.com（ZSTEK）从首次诊断到结果可信，历经 WAF 拦截、内页零样本、英文词根缺失、克隆页被当文章检查等 9 轮修复（进度㉒~㉛，版本 2026.09.09.3 → 2026.09.09.9）。期间业务方多次亲自验证网站实况才发现问题，AI 助手多轮"以为修好了"。本文复盘为什么会漏、以后怎么防。

## 一、暴露的系统性缺陷及根因

### 1. 检查器之间没有"链式认知"
最能说明问题的例子：E-E-A-T 署名检查的对象 `/adventure-news/`，被「页面与首页正文雷同」检查判定为 99% 克隆——**同一个爬虫产出的数据，一个检查器用它证明该页是垃圾，另一个检查器却把它当文章认真评署名**。根因：各检查器独立选页、独立结论，没有共享"这个页面已判定为克隆"的事实。
**已修**：选页器统一排除克隆页。**待建**：检查结果间的引用机制（如雷同判定应抑制对该页的其他内容级结论）。

### 2. "扫文本的正则默认是中文站"成为集体盲区
决策信息 0/5 误报、成立年份读不到、员工规模读不到——同一类根因重复犯了三次才被系统化：**30+ 处扫站内文本的正则里，约四成只有中文词根**。此前每次发现都是"点杀"单处，直到业务方拦下"别发给客户"才做了全量扫描。
**已修**：全量双语化 + 产出《英文站适配清单》+ 自查口诀（中文词/英文词/拼音词三问）。**预防**：新增文本类检查项必须过三问。

### 3. 抽样质量缺陷层层叠加，表现为"0 内页""没检查到"
ZSTEK 的内页抽样先后被三层问题盖住：WAF 拦截（403 当首页）、None 占位崩溃被静默吞掉（0 内页）、sitemap 文章页分类为 other 排最低优先级从未进样本。每一层单看都像"这个站没内容"，实际是管线坏了。
**已修**：403 换浏览器身份、None 过滤、sitemap posts 文章保底进样本、抽样扩容 15+6。

### 4. 缺陷"间接可见"但"病因未点名"
中文版页面正文是英文（/cn/history/ 中文占比 5%），报告只报了"标题重复""99% 疑似副本"两个症状，没说出"中文版是英文镜像"这个病因。业务方点开页面才看穿。
**已修**：content-06 新增语言一致性判定 + 导航未翻译识别。

### 5. 服务部署与代码版本脱节
出现过两次"本地已修、服务器仍旧版"的空窗：业务方拿旧报告反馈问题，排查成本高。
**已修**：报告嵌入 ENGINE_VERSION、诊断页标题显示版本号、Docker 时区/挂载固化、AGENTS.md 部署章节。

## 二、流程教训（对 AI 助手与维护者的要求）

1. **同类问题第二次出现必须升级为全量扫描**：单点修补（㉕⑯）各漏了下一处，直到㉗㉚改为括号配平扫描器 + 双语化审查才收敛。规则：第二次踩同一类坑 = 立即写扫描器全量排查，不再点杀。
2. **业务方实地核验优先于 AI 推断**：多轮误判（"单页站""sitemap 不存在"）均被业务方实地访问推翻。规则：对站点的任何断言（有/没有某页面）必须实际请求验证。
3. **异常静默 = 故障伪装成数据**：爬虫异常被吞成"0 内页"，看起来像正常结果。规则：任何 except 都不能只 pass——要么重试、要么如实报错、要么在结果里标注降级原因。
4. **修完必须证明"新版真的在跑"**：进程启动时间核对、报告版本号、诊断页版本显示，三件套缺一不可。
5. **报告要给"可执行的整改故事"而非分数**：ZSTEK 的五个问题拼起来是完整叙事（框架搭好、内容与多语言只完成一半），散落在 46 项打分表里客户看不到主线。**待建**：报告尾部"整改待办清单"区块，把全站 WARN/FAIL 按对象（页面/栏目/全站）归组为可勾选的行动项，含 sitemap 声明但未达标的具体 URL。
