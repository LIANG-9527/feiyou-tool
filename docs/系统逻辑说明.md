# 系统逻辑说明（业务口径落盘）

> 本文件按 AGENTS.md「落盘纪律」记录藏在字段、按钮、数据、判断、交互里的「为什么这么做」。
> 每条含：页面/流程路径、为什么、结果。

## 任务发起 → 企业档案（第一层工商与组织）

### 本地企业库人工录入可替代企业信息接口作为地基数据源（2026-11-10）

- **为什么**：企业信息接口（工商数据）查不到某些小微企业（实测：广州一介网络科技有限公司，接口查询返回为空、公开搜索引擎/第三方镜像站亦检索不到），按定版规则「接口通但返回为空 → 立即终止任务」，整条报告链路无法续跑。而档案管线本身存在设计好的旁路：本地企业库缓存若已含核心字段（全称+统一社会信用代码+法人）且基础字段≥5 个，会自动跳过接口调用直接续跑。因此对这类站点，允许人工从权威公开渠道（国家企业信用信息公示系统/爱企查/天眼查等）取得工商注册信息、经人工核验后录入本地企业库，作为地基数据来源——地基仍在，只是来源由接口改为人工核验录入，不推翻「无工商地基必须终止」的红线（禁止编造数据，录入值必须来自真实公开档案并经用户确认）。
- **结果**：录入后发起任务即命中缓存、跳过企业信息接口调用，后续流程（百科/官网/检测/报告）照常执行。已知边界：报告证据链中这批字段来源显示为「本地数据库缓存」，不区分接口/人工录入。（原边界②「组织图等环节仍真实调接口、接口异常即终止」已被同日「组织架构接口异常降级」定版取代，见下节。）
- **录入方式**：调用企业库现成写入通道（字段级合并、带来源标记），无代码改动。本次已按此录入广州一介网络科技有限公司 8 个字段（全称/信用代码/法人叶青/成立 2016-08-17/天河区注册地址/软件和信息技术服务业/参保 28 人/状态开业），来源标记「人工核验录入（爱企查工商注册截图）」，验证满足跳过门槛（核心 3 项齐、基础字段 7/9）。

## 任务发起 → 客户市场调研 → 组织架构实名图（落盘前）

### 接口异常/工商查无时组织图降级，不再终止任务（2026-11-10 用户定版）

- **为什么**：2026-09-20 定版「企业信息接口异常/查无 → 组织架构无法生成 → 终止任务」，当时的顾虑是没有工商地基的报告不可信。但地基职责已由本地企业库承接（见上节人工录入旁路），组织图环节缺的只是股东树明细；且接口账号欠费（余额不足）时整单报告（LLM 全流程已跑完约 5 分钟、token 已烧）在最后一步作废，代价不合理。现有代码本有「查无股东/分支机构 → 仅主体节点+组织图待补」的降级分支，接口异常只是数据来源换成本地企业库的人工核验主体，同一形状。
- **结果**：接口异常或查无时，若本地企业库有该主体（全称+信用代码齐），组织图降级为仅主体节点、标"组织图待补"（来源标记 local_archive），报告照常生成落盘；档案标 org_status=待重查，下次重生成自动重查、接口恢复即补全股东树。库里也无身份才维持终止报错。股权关系（如母公司持股明细）在降级报告中不出现。改动集中在组织架构生成函数本体，四个调用入口全走它。

## 登录门禁 → 账号与员工权限隔离（2026-11-16 定版）

### 多账号与角色
- 账号存 var/data/users.json（密码 pbkdf2 加盐哈希，明文永不落盘）；角色两档：总监/员工。首次启动用 .env 原总账号引导建总监账号，老部署零迁移。
- 登录名只能 2~40 位字母或数字（用户定版：不可中文/符号）。姓名可留空默认同登录名。
- 账号管理页（配置管理→账号管理，仅总监可见）：新增（弹窗）、重置密码、修改角色（弹窗选员工/总监）、启用/禁用（滑块开关）、删除。
- 为什么禁用而非删除：禁用即不可登录+存量会话立即踢下线，数据保留；删除才清归属。

### 保护规则（防锁死）
- 不能停用当前登录的自己；不能禁用最后一个启用中的总监；不能把最后一个启用中的总监改为员工；不能删除最后一个总监；不能删除当前登录账号。改密/改角色/禁用都会强制该账号重新登录。

### 员工数据隔离（口径：谁查询过算谁的）
- 企业归属存独立表（company 行走 INSERT OR REPLACE 整行重写，列会被抹，故独立表），多值：员工B再查A查过的企业，两人都可见。总监提交也登记归属（仅影响员工可见性）。
- 提交调研/挖掘/诊断/刷新任务时登记归属，报告 JSON 落"提交人"；旧无提交人报告按品牌归属回退判定；刷新回写一律不动原提交人（刷新者不得夺走可见归属）。
- 员工可见：自己归属企业的档案/任务/报告/诊断，自己提交的报告直链；配置管理整区（Skill管理/企业资料/操作日志/JSON补录/标注汇总/账号管理）仅总监（手敲地址/直打接口同样被拦），技能/方法/优先级配置可读不可改。存量无归属企业=公共：总监可见、员工不可见，由总监指派。
- 删除账号不删数据：名下企业归属清空转公共待指派。

### 门禁与导航
- 退出登录按钮注入各页导航栏最右侧末尾（无导航页兜底右下角浮钮；客户报告页不注入）。
- 配置管理下拉统一顺序：账号管理→Skill管理→企业资料→操作日志→JSON补录→版本说明；下拉与标题间的 12px margin 间隙用透明悬停桥（::before）覆盖，鼠标直落不再闪没。
- 对话不向员工开放（2026-11-16 定版）：一级菜单「对话」对员工隐藏，直敲 /chat 或调对话接口一律拦（页面弹回首页/接口403）；仅总监可用。

### 企业查询归属指派：把某企业的报告放开给指定员工看（2026-11-16 用户定版，方案B按企业）
- 为什么：员工默认只见"自己查询过"的企业；总监想把已有报告（如官网诊断）给某员工看，此前只能让员工重跑一次（浪费工商额度与 token）。
- 入口：企业资料页列表新增「查询归属」列+「指派」按钮（仅总监，整页仅总监可进）；弹窗勾选员工保存=整组替换，全部取消=转公共（仅总监可见）。
- 口径：指派按企业生效——被指派员工可见该企业档案、其调研/挖掘/诊断报告与任务；报告可见性判定改为"企业归属（含指派）优先、提交人兜底"（此前提交人一票否决，指派不生效）。
- 员工侧配套放开：企业档案只读接口（列表/明细）对员工 GET 放行并按归属过滤——员工无企业资料页入口，数据经分析页报告列表/直链生效；企业写操作（删除/别名/指派）仍总监专属。
