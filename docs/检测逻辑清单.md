# 检测项执行逻辑清单（供业务专家审核）

> ⚠️ **2026-09-10 V6 修订已落地**：本文各行的判定逻辑凡与
> `docs/修订规格-V6落地.md`（已全部实现）冲突的，**以规格为准**。主要变化：
> 20 项转"只提醒不计分"（含知识图谱、E-E-A-T、公司信息一致性、决策信息等）；
> 标题/描述改双轴判定（15~30 字符合格、堆砌形状才不合格、描述缺失降为不足）；
> 图片说明三态口径（留空剔除分母，80%/50% 两线）；
> 时效性与 AI 原创性拆分（原创只提醒）；robots 按 RFC 9309 解析并按 A/B 组名单分判；
> 规范化新增五项机检（指向站外/死链/noindex 等判不合格）；
> 占比类判定加最小样本保护（抽样 <6 页不判不合格）。
> 全量重写本文排期中，当前以本文+上方规格对照阅读。

> **本文档用途**：逐项列出诊断引擎 66 个检查项**实际在代码中执行**的检测规则、数据来源与判定标准，供业务专家统一审核「检查逻辑是否合理」。
> **编写方式**：逐条对照检查器源码实读提取（非宣传文案），含真实阈值数字。编写日期：2026-09-10，对应引擎版本 2026.09.09.13。
> **判定用语**：每项结论只有三种——合格 / 不足（warning，橙色）/ 不合格（fail，红色）；另有「未检查」（跳过，注明原因）。优先级 P0/P1/P2 只影响计分权重（2/1/0.5 票），不改变判定本身。
> **数据来源总述**：诊断时抓取首页 + 抽样内页（分层抽样：按页面类型保底 + 多样化补充，最多约 12~20 页），并对全站 URL 做一次轻量扫描（只取元数据）。另解析站点地图（嵌套最多 3 层）与 robots.txt。

## 一、技术可抓取性（22 项）

| 检查项 | 检查对象与数据来源 | 方式 | 实际判定逻辑（代码执行口径） | 跳过/不适用 |
|---|---|---|---|---|
| HTTPS 安全连接 | 首页最终跳转后的 URL（跟随重定向后） | 规则 | 最终地址以 `https://` 开头=合格；否则=不合格。**注意：不校验证书有效期、TLS 版本、HSTS**，只看协议头 | 无 |
| robots.txt | 请求 `/robots.txt` 原始文本 | 规则 | ① 对 8 个 AI 爬虫（GPTBot、ClaudeBot、Google-Extended、Bytespider、Applebot、ChatGPT-User、PerplexityBot、Cohere-AI）逐个用正则找「User-Agent: 该爬虫 … Disallow: /」→ 有封禁=不合格；② 文本含 `sitemap:` 行=合格；③ 文件存在但无 sitemap 引用=不足；④ 文件不存在=不足（提示"默认允许所有爬虫"）。**注意：只做逐段正则匹配，不解析通配符/优先级语义** | 无 |
| sitemap.xml 站点地图 | 优先 robots.txt 声明的地址，其次依次试 /sitemap.xml、/sitemap_index.xml、/sitemap.php、/sitemap；解析 `<url>` 条目（含 lastmod/changefreq），一层索引会再抓最多 5 个子地图 | 规则 | 合格基线=找到且能解析出 URL。在此基础上做质量检查：**硬问题（任一→不足）**：① >50% 网址主机与首选域不一致；② >50% 带 index.php 段；③ 站内已达「详情页/FAQ页」未收录进地图；④ 已 noindex 的页面仍留在地图。**软提示（不降级）**：含 CMS 演示页（hello-world/sample-page 等）、≥3 个网址 lastmod=检测当天、>80% lastmod 同一天、>50% 标 always/hourly | 全部打不开=不合格 |
| llms.txt（非必检） | 请求 `/llms.txt` | 规则 | 存在且 ≥20 字符=合格；不存在或过短=不足。**不计分**，只给建议 | 不计分 |
| .well-known AI 发现文件（非必检） | 探测 /.well-known/ai-plugin.json、llms-full.txt、llms.txt 是否存在 | 规则 | 任一存在=合格；全无=不足。**只查存在性，不校验 JSON 字段** | 不计分 |
| 页面可索引性 | 首页 meta robots 标签 + X-Robots-Tag 响应头 | 规则 | 含 noindex 或 nofollow（任一来源）=不合格；否则合格。**只查首页**，内页 noindex 不在此项查（由站点地图项的矛盾检查覆盖） | 无 |
| 网址规范化（canonical） | 首页+全部抽样内页的 `<link rel=canonical>` | 规则 | ① 任一页面 canonical 指向不同于自身的地址→不足（列明细，可能是故意的归一）；② 首页 canonical 指向自己=合格；③ 指向别的页面=不足；④ 没写=不足 | 无 |
| 跳转与状态码 | 首页响应状态码 | 规则 | 200=合格；3xx=不足；4xx/5xx=不合格。**只看首页状态码**（内页死链由「内部链接可访问性」查） | 无 |
| 内容可访问性 | 首页初始 HTML 的纯文本量（剥离脚本样式） | 规则 | 文本 <100 字符=不合格；100~500 且存在 noscript 标签=不足；≥500=合格 | 无 |
| 页面响应速度与体积 | 首页+全部抽样内页的 HTML 文档响应时间与体积，取中位数；另查 Content-Encoding | 规则 | **不合格**：响应中位数 >2s 或 HTML 中位数 >800KB；**不足**：中位数 >0.8s 或 >300KB，或未开 gzip/br 压缩；否则合格。注明这是文档下载耗时、非首屏渲染 | 无 |
| 移动端友好 | 首页 meta viewport | 规则 | 无 viewport=不合格；有且含 width=device-width=合格；有但异常值=不足。**不做真实渲染测试** | 无 |
| URL结构与可读性 | 全部抽样内页的 URL 路径（首页不查） | 规则 | 每页检查 5 点：① 含非跟踪类动态参数（?id= 等，排除 utm/gclid）；② 纯数字路径段；③ 路径 >4 层；④ 路径 >80 字符；⑤ 含下划线。有问题页占比 ≤30%=不足，>30%=不合格，0=合格 | 无抽样内页时跳过 |
| 内部链接可访问性（断链检测） | 首页+抽样内页里的全部同域链接，逐个发请求看状态码 | 规则 | 死链（404/5xx/无响应）<3 个=不足；≥3 个=不合格；0 个=合格。外链协议笔误（htts://）只进明细不判级；死链按导航>正文>页脚排序 | 仅抓首页（未抽样）时跳过 |
| HEAD/GET 状态码一致 | 首页+前 3 个抽样内页，对每页发 HEAD 请求对照 GET 状态码 | 规则 | HEAD 报错（≥400）而 GET 正常→不足（列明细）；全部一致=合格。HEAD 本身失败（无响应）不计 | 无抓取器时跳过 |
| 分享卡片标签(Open Graph) | 首页 og:* meta 标签；另抽第 1 个内页对照 | 规则 | 核心五项 og:title/description/image/url/type 缺 0 个=合格；首页全无或缺项=不足。内页不带 og 只追加提示 | 无 |
| 页面缓存与会话开销 | 首页响应头 Set-Cookie 与 Cache-Control | 规则 | ① 会话 Cookie（PHPSESSID 等）+ 禁止缓存（no-cache/private 且无 public）→不足；② 只有其一→不足；③ 都无=合格 | 无 |
| 安全响应头（非必检） | 首页 4 个安全响应头 | 规则 | HSTS、nosniff、X-Frame-Options/CSP、Referrer-Policy：缺 ≥3 个→不足（提示优先补 HSTS）；缺 1~2 个→不足；全有=合格。**不计分** | 不计分 |
| 多入口统一跳转(首选域) | 构造 http/https × www/非www 共 4 个入口，逐个不发跟随地探测跳转链（最多 3 跳） | 规则 | ① 某入口不跳转、直接 200 打开与首选域相同内容→不足（重复入口未收口）；② 收敛了但用 302/303/307 临时跳转→不足（建议 301）；③ 链路异常（跳到错误处/报错）→不足；④ 全部 301/308 收敛到首选域=合格 | 无抓取器时跳过 |
| 站内搜索页可索引性（非必检） | 爬取中识别到的搜索结果页（/search、?s=、?q= 等特征） | 规则 | 抓到的搜索页全部带 noindex→未检查（合规不报、不罚）；有可索引的搜索页→不足建议加 noindex；没发现搜索页→未检查 | 不计分 |
| 分页可抓取性（非必检） | 全部抽样页里找分页链接（page/2、?page=2 等） | 规则 | 有静态分页 href=合格；有分页 UI（class 含 pagination 等）但无静态链接→不足（JS 渲染分页，需人工复核）；没检测到分页=跳过 | 不计分 |
| CMS指纹识别（诊断项） | 首页 HTML/响应头/Cookie + Wappalyzer 特征库 + 国内 CMS 指纹库（含特征路径主动探测），按权重累计判置信度 | 规则 | 不参与评分，仅展示识别到的建站系统/技术栈及证据、置信度 | 诊断展示 |
| 后台路径暴露检测（诊断项） | 按配置库里的常见后台路径逐个 GET | 规则 | 可访问且是登录页：无验证码=不合格（诊断口径）、有验证码=不足；401/403 或 404=正常。不参与评分 | 诊断展示 |

## 二、AI友好度专项（14 项）

| 检查项 | 检查对象与数据来源 | 方式 | 实际判定逻辑 | 跳过/不适用 |
|---|---|---|---|---|
| Meta Title | 首页 `<title>` | 规则 | 无标签=不合格；<15 字符=不足；>80 字符=不足；15~80=合格。**注意：代码阈值（15/80）与页面上写的"30-60 字"建议口径不一致，实际按 15~80 判** | 无 |
| Meta Description-描述标签质量 | 首页 meta description | 规则 | 无=不合格；<50 字符=不足；>200 字符=不足；50~200 且含行动号召关键词（了解/咨询/联系/免费/立即/体验/试用/learn/contact/free 任一）=合格；50~200 无行动号召=不足 | 无 |
| 大标题唯一性与子标题层级结构 | 首页 H1/H2/H3 数量 | 规则 | 缺 H1、H1 多于 1 个、或只有 H1 没有 H2 子标题→不足（列明细）；恰好 1 个 H1 且有 H2=合格。**注意：H1 缺失/多个都只判"不足"而非不合格** | 无 |
| 结构化数据 | 首页 JSON-LD 与 Microdata | 规则 | 解析 JSON-LD 的 @type：含高价值类型（Product/Review/FAQPage/Article/Organization/LocalBusiness/Event/Recipe/BreadcrumbList/Service）=合格；有 JSON-LD 但无高价值类型=不足；无 JSON-LD 但有 Microdata=合格；全无=不合格 | 无 |
| AI 答案格式优化 | 首页+内容详情页（站点地图声明文章优先）的 ol/ul/table/dl/FAQ class | 规则 | 数命中的结构种类：≥2 种=合格；1 种=不足；0 种=不合格 | 无 |
| 面包屑导航（非必检） | 内容详情页（挑选规则见附录）：JSON-LD BreadcrumbList 或 class 含 breadcrumb 的 DOM | 规则 | 有 BreadcrumbList 标记=合格；只有 DOM 无标记=不足；全无=不足 | 抓不到内容详情页→未检查（需人工复核），不计分 |
| 站内链接丰富度 | 首页站内链接去重数 | 规则 | ≥5 个=合格；1~4 个=不足；0=不合格。**注意：合格线是 5 个，页面上写的建议是"每页≥3条内部链接指向"** | 无 |
| 搜索引擎/AI 平台验证 | 首页 5 种站长平台验证 meta（google/baidu/bing/360/sogou） | 规则 | 任一存在=合格；全无=不足。**只查验证标签，无法验证是否真的提交了 sitemap** | 无 |
| NLP/大模型语义友好度 | 内容详情页正文 | AI | 大模型按提示词评审：概念是否先定义、指代是否明确、事实是否"主语+结论+依据"完整；双次生成共识后出合格/不足/不合格 | 未配置大模型→未检查；抓不到内容详情页→未检查（需人工复核） |
| 内容分块与逻辑组织 | 内容详情页正文 | AI | 大模型逐块判断：标题与内容是否匹配、块间是否按"是什么→为什么→怎么做"递进、单块是否过长 | 同上 |
| Title/Description 唯一性 | 首页+全部抽样内页的 title 与 description 文本 | 规则 | 完全相同的文本出现在 ≥2 页记一组重复：重复组数 <3=不足；≥3=不合格；无重复=合格。**注意：只比对完全相同，相似但不同不算** | 仅抓首页时跳过 |
| 内页标题与描述规范 | 全部抽样内页逐页检查 | 规则 | 每页查：缺标题/标题<15 字/标题>80 字/缺描述/描述<50 字（**不查描述超 200**）。有问题的页占比 ≥50%=不合格；>0 且 <50%=不足；0=合格 | 无抽样内页→未检查 |
| 内页主标题(H1)唯一性 | 全部抽样内页逐页统计 H1 数量 | 规则 | H1 数≠1 即该页不达标（0 个或多个）；另：详情类页面有正文 ≥200 字却全页无 H2/H3 也算不达标。不达标占比 ≥50%=不合格；>0=不足 | 无抽样内页→未检查 |
| 详情页结构化数据 | 抽样中的详情类页面（按网址段判定） | 规则 | 每页查有无 JSON-LD 或 Microdata，全无的页占比 ≥50%=不合格；>0=不足；0=合格 | 无详情页抽样→未检查 |

## 三、内容质量与结构化（12 项）

| 检查项 | 检查对象与数据来源 | 方式 | 实际判定逻辑 | 跳过/不适用 |
|---|---|---|---|---|
| 核心内容深度 | 首页纯文本字数 | 规则 | <200 字=不合格；200~500=不足；≥500=合格 | 无 |
| 内容原创性与时效性 | 首页+全部抽样内页（字数>100 的页）：① time 标签/article:published_time/article:modified_time 有无；② 内容详情页交 AI 判原创性 | 规则+AI | 有时间标注的页占比（时间标注结论为主、AI 原创结论为辅）：占比 ≥80%：有 AI 时直接采纳 AI 结论，无 AI=合格；占比 30%~80%：一律不足（AI 只补充说明）；占比 <30%：AI 判不合格→不合格，其余一律不足（AI 判合格也不能升为合格）。综合时两段结论拼接展示 | 无内容页→未检查 |
| FAQ 问答结构 | 首页+全部抽样内页：FAQPage JSON-LD；dt/details/含？的 h3~h5/button 文本算"问答条目"（位于 footer/aside 的定性为模板复制） | 规则 | 任一页有 FAQPage 标记=合格（另有无标记板块页则附提示）；无标记但有 FAQ 板块=不足（并列出涉及页与跨页重复率）；全站无=不足 | 无 |
| 图片与多媒体优化 | 首页全部 img | 规则 | 无效 alt 三类：空、模板残留（{{xx}}、eyou 等）、无意义占位（"图片"/"image"/单字符）。有效 alt 覆盖率 100% 且坏文件名（img1.jpg/纯数字等）<30%=合格；无效占比 <30%=不足；≥30%=不合格 | 页面无图片→未检查 |
| 内部链接布局 | 首页站内链接锚文本（<20 字的） | 规则 | 无意义锚文本（点击这里/了解更多/详情等 10 个词）占比 0=合格；<40%=不足；≥40%=不足（同档，仅文案更重）。**注意：两档都是不足，占比再高也不会不合格** | 无内链→未检查 |
| 多语言/多地区设置（非必检） | 全部抽样页：hreflang、语言切换器、/cn//en/ 路径、html lang | 规则 | 无语言切换器且只识别出单一语言=未检查（单语言站不适用）；有中英版本时逐中文页与英文页算字符相似度：≥70% 判"半成品镜像"=不合格；无镜像：有 hreflang=合格，只有切换器无 hreflang=不足 | 不计分 |
| 搜索意图匹配 | 内容详情页 | AI | 大模型识别页面核心关键词与意图类型（学知识/比方案/直接买），判断内容类型是否错位 | 未配置大模型→未检查；抓不到详情页→未检查（需人工复核） |
| 关键词蚕食检测 | 全部抽样页标题 | 规则 | 去品牌词（出现 ≥2 次的分隔片段视为品牌）后取标题主题，两两算字符相似度：≥70% 记一对疑似。≥3 对=不合格；1~2 对=不足；0=合格。注明是规则初筛、建议人工确认 | 仅抓首页时跳过 |
| 内页正文厚度 | 全部抽样内页逐页字数 | 规则 | <500 字记问题（<200 标"过薄"、200~500 标"偏薄"）。问题页占比 ≥50%=不合格；>0=不足；0=合格 | 无抽样内页→未检查 |
| 内页图片说明(alt)覆盖 | 全部抽样内页逐页算 alt 覆盖率（只统计含图内页） | 规则 | 某页覆盖率 <50% 该页记问题。问题页占比 ≥50%=不合格；>0=不足；0=合格 | 内页无图→未检查 |
| 必备页面完备性 | 全站 URL 清单（站点地图+两层内链+首页链接）按网址栏目分类，另识别首页锚点区块形态 | 规则 | 强必备 4 类：关于我们、产品/服务、FAQ、隐私政策。缺 0 类=合格；缺 1~2 类=不足；缺 ≥3 类=不合格。客户案例/资讯/独立联系页/帮助/资质 5 类只提示不判分 | 无页面清单→未检查 |
| 页面与首页正文雷同 | 首页+全部抽样内页，剥离模板后只比正文主体，两两算字符相似度 | 规则+AI | 相似度 >85% 记"疑似对"；有 AI 时逐对交 AI 终审：有 AI 判重复的对→不足，AI 全判不同→合格；无 AI：疑似 <3 对=不足、≥3 对=不合格 | 无抽样内页或首页正文 <200 字→未检查 |

## 四、权威与信任信号（8 项）

| 检查项 | 检查对象与数据来源 | 方式 | 实际判定逻辑 | 跳过/不适用 |
|---|---|---|---|---|

## 附：通用机制（专家审阅时需要知道的口径）

1. **内容详情页怎么选**（影响面包屑、语义友好度、内容分块、搜索意图、E-E-A-T 五项）：从抽样内页中挑"检查对象页"。优先级：① 站点地图「文章清单」子地图声明的文章页（站长认定+引擎可验证）；② 网址含 article/blog/news/post/案例/产品等关键词的页面；③ 正文最长的页面。与首页高度雷同的克隆页、字数 ≤100 的页会被排除。一个都挑不到时，上述五项统一标「未检查（需人工复核）」，按中性 0.5 计入分母，不直接判不合格。
2. **AI 检查的可复现机制**：每个 AI 检查项会独立生成两次并取共识（结论不一致时降档处理），减少单次随机性；但大模型结论本身仍具有概率性，同一站点两次诊断的 AI 项结论可能不同。
3. **部分 AI 项的固有局限**：知识图谱品牌实体、跨平台内容分发两项依赖大模型的训练期知识，**不是实时联网查询**，对新站/小品牌可能误报"无实体/无分发"，此类结论建议专家人工复核后再采信。
4. **抽样机制**：诊断只抓首页+抽样内页（分层抽样 12~20 页）+全站 URL 轻量扫描（仅元数据）。因此"全站级"检查项的实际覆盖范围=抽样页+全站 URL 清单，不是逐页全文检查；未被抽样到的页面问题可能漏检。
5. **用语统一**：所有检查项结论只有合格/不足/不合格三种状态词；「不足」是警告级（橙色），不等同于不合格。
